# Premise Recovery

Adapted from g3stack's recovery procedure and pstack Attack the Premise.
Reuse the current project record and preserve rejected assumptions and failures.

| Finding | Next action |
| --- | --- |
| Code violates an unchanged supported contract | Diagnose and fix through [Debug](../g3-debug/SKILL.md). |
| A load-bearing premise is contradicted | Retain the counterexample and investigate that premise. |
| Source, environment or data conditions changed | Verify changed conditions and revalidate affected evidence. |
| Cause remains ambiguous | Choose a bounded check separating plausible explanations. |
| Resolution changes owner scope, criteria or budget | Surface that decision and continue independent authorized work. |

For the affected assumption, record its claim, conditions, supporting/counter
evidence and dependent decisions/artifacts. Mark a refuted premise rejected or
superseded, reopen only its affected dependents and retain unrelated valid work.
Preserve accepted success criteria. Add a meaningful failure check where relevant
and record why the next action changed.

Inspect a shared premise when repeated fixes fail, or at the first clear
counterexample. Do not repeat a known failure to meet a threshold. State the
premise in one sentence, identify an observation that differs if it is false,
and test it before another fix that assumes it.

Return the result and limitations to Core's project decision loop. If another
attempt cannot add evidence or meet an accepted requirement, change the check
or surface the actual decision. Recovery adds no second lifecycle or new state system.
