# Experiment

1. State the hypothesis, competing explanations and which decision each possible
   outcome can change. Define success, stop conditions and resource bounds before measurement.
2. Define a baseline, control where appropriate, representative inputs, provenance,
   inclusion rules and confounders. A convenient fixture is not a real population.
3. Specify procedure, relevant metrics, validity checks, uncertainty and artifact
   destinations. Freeze inputs, labels, scoring and comparison conditions before
   candidate inspection when independence is required; record contamination.
4. Separate tuning/development from final assessment. Keep model, tools,
   environment and permissions controlled in agent comparisons; vary the intended
   intervention only. Check scorers with known cases and independent expected values.
5. Verify the authorized venue, data, versions, fit, logging and recovery. Follow
   personal compute, spending and quota limits. A design request does not authorize a run.
6. Execute only authorized bounded work. Retain source/input identity, parameters,
   commands, seeds, raw results, logs, failed checks and protocol deviations.
   Validate output completeness before analysis.
7. Compare against the predefined baseline and criteria. Report effect size,
   variation, failures, missing data and confounders. Distinguish an executed run
   from a supported hypothesis or achieved goal. A single pilot is not a general claim.

For performance or agent-specific technique use [Measurement](../g3-measure/SKILL.md).
Assess outcomes independently of agent-written tests or self-reports when feasible.
Return evidence and limitations to the existing project record; do not force
another iteration merely because a technique is available.
