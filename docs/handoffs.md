# Bounded capability handoffs

Use `scripts/handoff.py` when g3stack selects an existing native skill for a
specific subtask. This optional helper implements a brief and an evidence
return gate. It adds no skill registry, model service, scheduler, or global
configuration. Existing permissions and the
[capability contract](capability-integration.md) still apply.

## Ownership and sequence

1. g3stack identifies the project goal, current gap, and authorized subtask.
2. Inspect the active host catalog. Select a compatible skill, read its full
   instructions and required resources, and check dependencies and conflicts.
   A filesystem folder is insufficient evidence of native discovery.
3. Prepare a handoff. It binds the goal, task, acceptance criteria, skill
   source fingerprint, discovery evidence, allowed writes, and stop boundary.
4. The active host applies the selected skill within that subtask. This can
   happen in the same agent session. A subagent is optional and requires host
   support and applicable authorization. The helper does not launch one.
5. Capture actual command outputs and artifacts. Retain failed checks. Return
   a result envelope to g3stack, then run the evidence gate.
6. g3stack independently checks the result and chooses the next action. A
   completed subtask never automatically establishes project completion.

An external kit can supply a selected skill or a bounded workflow when its
native entry point, dependencies, and permissions are compatible. Keep sibling
resources intact. This helper fingerprints the selected directory only;
review and record external dependencies separately. It does not adapt an
unsupported kit to Codex or certify pstack compatibility.

## Prepare a brief

Example for the system `openai-docs` skill on the current owner's Codex setup:

```sh
python3 -B scripts/handoff.py prepare \
  ~/.codex/skills/.system/openai-docs \
  --host codex \
  --workspace "$PWD" \
  --goal 'Preserve the active Codex integration.' \
  --task 'Perform a read-only audit of the g3stack global instructions and router link.' \
  --acceptance 'The integration checker reports matching installed instructions and router source.' \
  --discovery-evidence 'The active Codex session catalog lists openai-docs at this source.' \
  > /tmp/g3-handoff.json
```

Use the source actually listed in the current host catalog. The example path
is machine-specific. `prepare` only prints JSON; shell redirection saves it.
Its `prompt` field is the complete English brief for the selected capability.
Treat the catalog evidence as a claim to verify, not as proof generated by
the script. Manual-only skills are rejected unless `--explicit-invocation`
records an actual explicit user request; the flag itself grants no authority.

An empty `allowed_writes` list means the subtask is read-only. Add
`--allow-write workspace/relative/path` for each authorized file or directory.
This does not replace sandbox enforcement. Logs captured by the orchestrator
are separate from writes performed by the capability.

## Check returned evidence

The brief describes the result fields: `handoff_id`, `status`, `summary`,
`checks`, `artifacts`, `changes`, and `open_issues`. Each acceptance criterion
has an ID such as `C1`. Each check records that ID, the actual command and
exit status, and a workspace-relative log with its SHA-256. Artifact records
likewise bind a path and SHA-256.

```sh
python3 -B scripts/handoff.py check /tmp/g3-handoff.json /tmp/g3-result.json
```

| Result | Exit | Orchestrator action |
| --- | --- | --- |
| `READY_FOR_REVIEW` | 0 | Independently verify the checks and artifact meaning; reassess the goal. |
| `BLOCKED` or `FAILED` | 1 | Preserve the open gap and choose an authorized next action. |
| `REJECTED` | 2 | Diagnose invalid, changed, missing, or out-of-scope evidence. |

The gate rejects a changed contract or skill source, missing criteria,
failed checks reported as completed, modified evidence, paths escaping the
workspace, and reported writes outside the allowed scope. It never executes
commands returned by a skill. A valid envelope cannot prove that its author
ran a command, interpreted a result correctly, or disclosed every write.
The parent must check actual execution receipts and resulting state.
Checksums detect drift, not malicious rewriting of a contract and its hash.

## Regression checks and evidence limits

```sh
python3 -B scripts/test-handoff.py
python3 -B scripts/test-capabilities.py
python3 -B scripts/test-codex-integration.py
python3 -B scripts/check-codex-integration.py
```

The handoff suite uses isolated fixtures and the actual CLI. It tests scope,
evidence integrity, manual invocation, incomplete results, failure handling,
and return to the orchestrator. It makes no model calls. These tests do not
establish automatic skill selection or generalized agent effectiveness.

## Copy-ready request for the active Codex session

```text
Use $g3stack to coordinate the current project goal. Select one suitable
skill from the active host catalog only when it helps resolve the next gap.
Resolve the installed g3stack checkout, apply its docs/capability-integration.md,
and use its scripts/handoff.py to prepare a bounded brief and
check returned evidence when the subtask warrants a recorded handoff.
Keep project-goal decisions in g3stack. Verify discovery, dependencies,
permissions, actual outputs, and the applicable acceptance criteria.
If the capability is unavailable or incompatible, continue directly when
feasible. Do not install or activate anything, start paid jobs, commit,
push, deploy, or contact others without the required authorization.
Report the result, its evidence, and the next justified action in Vietnamese.
```

This request uses the helper in the current session. It does not activate a
new global policy. The existing global router remains unchanged.
